# 실제 리뷰 평가 자료 작성

코드 기능 시험과 실제 리뷰 정확도 평가를 구분합니다. 생성 예제와 사전을 만든 Codex의 자동 판정을 정답으로 간주하지 않습니다.

1. 카페별로 개발용·검토용·최종 평가용을 분리합니다. 초기에는 테라로사 강릉본점은 개발, 어니언 안국점은 개발 검토, 레이어드 안국점은 보류 평가 자료로 둡니다.
2. 가능한 경우 두 사람이 독립적으로 리뷰를 읽고 카테고리·평가 구절·감성 방향을 표시합니다.
3. 긍정·부정·중립·혼합·평가 없음·판단 불가를 구별합니다. 단순 메뉴 주문과 특징 서술에는 긍정 점수를 부여하지 않습니다.
4. 사전 결과를 보지 않고 정답을 먼저 작성합니다. 다른 카페에 대한 비교·과거 경험·인용·희망은 현재 카페 평가와 구별합니다.
5. 의견 차이를 기록하고 합의한 기준 자료를 만듭니다. 사람이 검토하지 않았다면 검토자 필드를 Codex로 표시하고 임시 평가라고 명시합니다.
6. 최종 평가 카페의 오류를 보고 사전을 수정했다면 그 자료는 더 이상 독립 최종 평가로 사용하지 않습니다.

평가 양식은 `review_id,cafe_id,category,gold_label,evidence_text,reviewer,notes`입니다. 원문과 평가 구절은 비공개 영역에 저장합니다. 카테고리 F1과 감성 macro F1, 혼동행렬, 미판정 비율을 별도로 평가합니다. 사람이 작성한 정답이 확보되기 전에는 정확도 수치를 보고하지 않습니다.
