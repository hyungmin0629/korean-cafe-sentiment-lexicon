# 초기 검증 결과와 한계

기준일: 2026-10-12. 코드·사전·규칙 버전 0.1.0.

## 기능 검증

`python -m unittest discover -s tests -v`의 15개 테스트가 통과했다. 서로 다른 평가 대상, 부정·이중 부정, 산미의 문맥, 중립과 혼합, 언급 없음, 인용·희망 판정 제외, 긴 구절 우선, 근거 좌표, 메뉴 별칭, 빈 달·날짜 누락, 리뷰별 동일 가중, 중복·잘못된 날짜·기간 필터·덮어쓰기 방지를 확인했다. 실제 개발 자료의 표현 변형과 재방문 구절의 절 분리 오류도 회귀 시험에 포함했다.

이는 정한 기능 사례의 통과이며 실제 리뷰 정확도 100%를 뜻하지 않는다.

## 실제 입력 실행

실제 카페 3곳의 수집 레코드 350건 중 빈 본문 17건을 제외한 333건에서 분석·집계를 완료했다. 전체 기간 결과 24행(카페 3 × 항목 8)과 월별 결과를 저장했다. 감성 근거를 하나 이상 얻은 리뷰는 299건이며, 절의 일부 근거가 확인 필요인 리뷰도 이 수에 포함될 수 있다.

사람이 작성한 정답이 없어 정밀도·재현율·F1·정답률은 아직 계산하지 않았다. 보류 평가용 카페의 항목별 집계는 실행 확인에만 사용했고 해당 원문을 보고 사전을 수정하지 않았다. 개발 카페의 누락 표현 15개를 추가했다.

## 처리 성능

Windows 11, Python 3.12.7에서 다음과 같이 측정했다.

| 생성 리뷰 수 | 분석·집계 시간 | 초당 리뷰 수 | 프로세스 최고 메모리 |
|---|---:|---:|---:|
| 10,000 | 1.309초 | 7,638.6 | 24.37 MiB |
| 100,000 | 13.230초 | 7,558.8 | 24.57 MiB |

입력은 짧은 예문 4개를 반복하며 카페 10개·월 12개로 구성했다. CSV 읽기, 중복 ID 집합, 상세 JSONL 쓰기 비용은 이 측정에 포함하지 않는다. 긴 실제 리뷰나 많은 사전 항목에서는 더 오래 걸릴 수 있다. 메모리는 동일 프로세스에서 두 규모를 순서대로 처리한 Windows 최고 작업 집합 크기다. 원본 측정 결과는 `benchmark.json`에 있다.

## 현재 한계와 수정 우선순위

1. 형태소 분석기 없이 어간 정규식을 사용한다. 일부 붙여 쓰기·오탈자·신조어·복잡한 활용은 누락된다.
2. 평가 대상은 가까운 단서로 연결한다. 실제 수식 관계와 다를 수 있고, 대명사나 비교 카페를 잘못 연결할 수 있다.
3. 인용·조건·희망 규칙은 절 전체를 보수적으로 제외한다. 같은 절에 직접 평가가 있어도 누락될 수 있다.
4. 반어, 긴 부정 범위, 과거 경험과 현재 평가, 사실과 취향 구별에는 한계가 있다.
5. 촉촉함·바삭함·신선함 등은 후보 사전에서 기본 긍정으로 둔다. 취향이나 반어가 섞인 실제 표현을 추가 검토해야 한다.
6. 공개 추천순 표본은 출처와 추천 알고리즘의 편향이 있다. 카페 전체 고객이나 모든 플랫폼의 평가를 대표하지 않는다.
7. 입지·친절·청결·운영은 분석 근거가 적은 경우가 많다. 사전 누락과 실제 언급 부족을 정답 자료로 구분해야 한다.

다음 품질 검증에는 원문을 직접 읽은 사람 정답, 별도 평가 카페, 카테고리별 오류 분석이 필요하다. 미판정 문장을 무조건 중립으로 채워 판정률을 높이지 않는다.
