# 수동 리뷰 준비·CSV 변환 안내

네이버 플레이스를 각자 수집하는 코드가 필요한 경우 [네이버 크롤러 안내](naver_crawling.md)를 먼저 보세요. 이 문서는 이미 확보한 자료를 정리하거나 수동으로 입력할 때의 대안입니다.

한 카페·한 지점의 리뷰를 파일 하나로 준비합니다. [빈 Excel 양식](../examples/review_input/리뷰입력_빈양식.xlsx) 또는 [빈 CSV 양식](../examples/review_input/리뷰입력_빈양식.csv)을 사용하세요. 입력할 것은 **리뷰본문**과 **리뷰작성일**입니다. 카페 이름과 지점은 변환할 때 한 번 입력합니다.

## 1. 매장과 리뷰 범위 확인

네이버에서 카페를 찾아 플레이스의 매장명·지점·주소를 확인하고 매장 링크를 따로 기록합니다. 사용할 기간이나 ‘최근 확인 가능한 리뷰부터 몇 건’ 같은 범위를 정합니다. 실제로 사용한 정렬 방식과 범위도 기록하면 이후 결과를 비교하기 쉽습니다. 특정 감성의 리뷰만 골라 넣지 마세요.

**방문자 리뷰의 고객 본문**을 대상으로 준비합니다. 방문자 리뷰는 방문 인증 등을 통해 작성한 후기를 제공하는 영역입니다. [네이버 고객센터 설명](https://help.naver.com/service/19485/contents/12843?lang=ko&osType=MOBILE)

블로그 후기, 매장 답글, ‘음식이 맛있어요’ 같은 선택 키워드·키워드 집계, 사진 설명이나 방문 횟수는 고객 본문에 섞지 않습니다. 본문이 접힌 경우 확인 가능한 전체 본문을 사용하세요. 파일을 내보내거나 제공받는 경로가 있으면 그 파일에서 해당 두 열을 정리해도 됩니다. 이 안내는 네이버에 우리 양식의 CSV 다운로드 기능이 있다고 전제하지 않습니다.

## 2. 한 리뷰를 한 행에 입력

| 열 이름 | 입력 방법 |
|---|---|
| 리뷰본문 | 원문을 한 셀에 그대로 입력. 쉼표·줄바꿈·이모지를 유지하고 감성을 요약하거나 수정하지 않음 |
| 리뷰작성일 | 작성한 날짜를 확인할 수 있으면 `2026-09-15` 형태로 입력. 확인할 수 없으면 빈칸 |

1행의 열 이름은 바꾸지 않습니다. 본문은 A열, 작성일은 B열이며 2행부터 입력합니다. 두 칸은 원문과 날짜 표시의 임의 변환을 막기 위해 텍스트 형식입니다. 양식에 예약된 100행보다 리뷰가 많으면 아래로 계속 추가할 수 있습니다. 다른 카페는 파일을 따로 만듭니다. 감성·카테고리·점수는 입력할 필요가 없습니다.

날짜는 리뷰 작성일을 기준으로 합니다. 방문일만 보이거나 작성일인지 구분이 어려우면 작성일은 비웁니다. 연도가 빠진 `9.15`, `어제`, `3일 전` 등의 표시에서 날짜를 추측하지 않습니다. 그런 표시를 작성일 칸에 적어 두면 변환 도구가 원본 표시를 별도 열에 보존하고 분석 날짜를 비워 둡니다. 비어 있거나 해석할 수 없는 날짜는 전체 기간 분석에 포함할 수 있으며 월별 분석에서는 제외합니다. 방문일과 작성일이 구분되는 정렬이 제공된 사례는 [네이버 안내](https://new.smartplace.naver.com/notices/510)를 참고하세요. 화면별 표시를 실제로 확인해 적용합니다.

작성자 닉네임·프로필·연락처·사진은 입력하지 않습니다. 본문 자체에 개인 연락처가 있으면 파일 공유 전에 해당 정보를 제거합니다. 실제 리뷰 파일과 결과는 비공개로 관리합니다. 사용할 수 있는 자료와 허용된 제공 경로로 준비하며, 네이버 자동 수집을 실행하는 안내가 아닙니다. [네이버 이용약관](https://policy.naver.com/policy/service.html)

## 3. CSV UTF-8로 저장

Excel 양식을 사용한 경우 입력한 시트를 **CSV UTF-8(쉼표로 분리)** 형식으로 저장합니다. CSV는 한 시트만 저장합니다. 본문 안의 쉼표·줄바꿈은 Excel이 CSV 규칙에 맞춰 처리하므로 CSV 텍스트에서 수동으로 행을 나누지 마세요. Excel 파일은 편집 원본으로 보관할 수 있지만 현재 분석기는 CSV를 사용합니다.

실제 파일은 프로젝트의 `data_private/` 안에 보관합니다. 자체 작성 예제는 [작성 예제 CSV](../examples/review_input/리뷰입력_작성예제.synthetic.csv)에 있으며 실제 리뷰와 합치지 않습니다.

## 4. 분석용 CSV로 변환

현재는 저장소 폴더에서 다음 명령으로 변환합니다. 업로드 화면은 후속 개발입니다.

```powershell
python tools/prepare_review_csv.py --input data_private/나리나무_리뷰입력.csv --cafe-name "카페나리나무 서울용산" --cafe-id narinamu --output outputs_private/narinamu_prepared
```

카페명과 지점은 한 번만 입력합니다. 같은 지점에는 같은 `--cafe-id`를 사용하세요. ID를 생략하면 입력한 카페 이름에서 자동 생성하므로 카페명 표기를 계속 동일하게 유지해야 합니다. `--place-url`로 매장 링크를 선택적으로 기록할 수 있습니다.

출력 폴더에는 다음 파일이 생깁니다.

| 파일 | 내용 |
|---|---|
| reviews.csv | 자동 리뷰 ID·카페 정보·출처 `naver_place`와 본문·날짜를 담은 분석용 CSV |
| preparation_issues.csv | 날짜 미상·날짜 오류·동일 행 반복과 확인할 위치 |
| preparation_metadata.json | 카페 정보, 준비 방식, 입력 해시와 건수 |

날짜는 `YYYY-MM-DD`, `YYYY.M.D`, `YYYY/M/D`를 정규화합니다. 달력에 없는 날짜나 연도 없는 표시는 보존하고 분석 날짜를 비웁니다. 날짜만 있고 본문이 없는 행, 잘못된 열 수, 빈 입력은 수정할 오류로 안내하며 출력하지 않습니다. 완전히 빈 행은 무시합니다. 동일 본문·날짜가 반복되면 확인 목록을 만들고 각 행을 유지합니다. 서로 다른 실제 고객의 같은 문장일 수 있으므로 자동 삭제하지 않습니다.

리뷰 ID는 입력 내용과 날짜 및 동일 행의 등장 순서로 만들어집니다. 네이버의 원래 리뷰 ID가 아니므로 파일을 수정하거나 기간을 겹쳐 추가할 때의 중복 관리는 확인이 필요합니다. 별점·수집일은 추정해 채우지 않습니다.

변환 후 보고서를 만들려면 실행합니다.

```powershell
python run.py --input outputs_private/narinamu_prepared/reviews.csv --output outputs_private/narinamu_report --period month
```

실행 후 결과 폴더의 `report.html`을 엽니다. 모든 작성일이 비어 있다면 `--period all`로 전체 기간을 분석합니다. 기존 결과를 덮어쓰지 않도록 새 폴더를 사용하세요.

## 자체 작성 예제로 먼저 확인

다음 예제는 기능 확인용이며 실제 나리나무 리뷰가 아닙니다. 출처도 `synthetic`으로 지정합니다.

```powershell
python tools/prepare_review_csv.py --input examples/review_input/리뷰입력_작성예제.synthetic.csv --cafe-name "입력 예제 카페" --source synthetic --output outputs_private/input_example_prepared
python run.py --input outputs_private/input_example_prepared/reviews.csv --output outputs_private/input_example_report --period month
```

## 저장 전 확인

- 한 파일에 한 지점의 고객 본문이 들어 있는지 확인합니다.
- 예제 문장·매장 답글·집계 키워드가 섞이지 않았는지 확인합니다.
- 한 리뷰가 한 셀·한 행인지, 임의로 요약하거나 줄바꿈을 행으로 나누지 않았는지 확인합니다.
- 작성일을 확인한 범위만 입력하고 모르는 날짜는 비워 둡니다.
- CSV UTF-8로 저장하고 준비 중 실수로 같은 리뷰를 두 번 붙여 넣지 않았는지 확인합니다.
